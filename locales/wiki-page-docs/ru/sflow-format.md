# 📄 Формат файла `.sflow`

Формат `.sflow` — это нативный стандарт обмена и сохранения **FloWorks**. Он позволяет упаковать полный рабочий поток в один файл, включающий топологию графа, параметры узлов, обработанные данные и стикеры, облегчая совместное использование, архивирование или детерминированное воспроизведение экспериментов.

---

## 📦 Что такое файл `.sflow`?

Файл `.sflow` по сути представляет собой **переименованный ZIP-архив**. Изменив его расширение на `.zip`, вы можете просмотреть его содержимое с помощью любого файлового менеджера или инструмента командной строки.

Его минимальная внутренняя структура состоит из:

| Компонент | Опиание |
|-----------|----------|
| `diagram.json` | Главный манифест: определяет узлы, соединения, вид, стикеры и метаданные сериализации. |
| `data/` | Папка с данными каждого узла в формате `.npy` (бинарные массивы NumPy). |
| `metadata.json` *(опционально)* | Дополнительная информация: автор, версия FloWorks, описание и теги. |

=== "🌳 Визуальная структура"
    ```text
    mi-flujo.sflow
    ├── diagram.json
    ├── metadata.json
    └── data/
        ├── node_1.npy
        ├── node_2.npy
        └── script_state.npy (опционально, для ScriptNode persist)
    ```

---

## 🧩 `diagram.json` – Сердце потока

Этот JSON-файл описывает полную топологию, положение элементов на холсте и состояние вида на момент сохранения.

### Минимальный пример
```json
{
  "nodes": [
    {
      "id": "n1",
      "type": "OscilloscopeNode",
      "pos": [150, 200],
      "params": { "channel": "primary", "simulation": false }
    },
    {
      "id": "n2",
      "type": "GraphExporterNode",
      "pos": [450, 200],
      "params": { "theme": "dark", "export_format": "png" }
    }
  ],
  "connections": [
    {
      "from": "n1",
      "to": "n2",
      "from_port": "out",
      "to_port": "data_in"
    }
  ],
  "viewport": { "x": 0, "y": 0, "scale": 1.0 },
  "stickers": [
    { "x": 600, "y": 100, "width": 200, "height": 150, "text": "Revisar umbral", "user_modified": true }
  ]
}
```

### Основные поля
| Поле | Тип | Описание |
|------|-----|----------|
| `nodes` | `Array` | писок объектов `{id, type, pos, params}`. `type` должен совпадать с `node_registry.py`. |
| `connections` | `Array` | Список соединений `{from, to, from_port, to_port}`. Порты — строки, не индексы. |
| `viewport` | `Object` | `(x, y, scale)` для восстановления точного положения и масштаба холста. |
| `stickers` | `Array` | Сериализованные стикеры с координатами, нормализованными к 96 dpi. |

!!! tip "Сериализация узлов"
    Специфические параметры каждого узла управляются через `SerializableMixin`. Сохраняются только атрибуты, объявленные в `SERIALISABLE = [...]`. Узлы, не зарегистрированные в системе, автоматически пропускаются при загрузке.

## 💾 `data/` – Обработанные данные и массивы NumPy

Когда поток выполняется, узлы могут храниь свои результаты в файлах `.npy` внутри этой папки.

- Имя файла обычно совпадает с `id` узла или с внутренними ссылками.
- Массивы хранятся в бинарном формате NumPy, **строго сохраняя исходную размерность** (1D, 2D, 3D и т.д.). Движок никогда не применяет `flatten()`.
- В `diagram.json` данные ссылаются с префиксом `__npy__:`:
  ```json
  "params": { "cached_output": "__npy__:node_2.npy" }
  ```
- Если узел не производит данных или настроен на их несохранение, соответствующий файл может отсутствовать.

??? note "Внешняя совместимость"
    Файлы `.npy` универсальны в экосистеме Python. Вы можете читать их вне FloWorks с помощью:
    ```python
    import numpy as np
    datos = np.load("data/node_1.npy")
    print(datos.shape)
    ```

## 🏷️ `metadata.json` (Опционально)

Содержит описательную информацию, не влияющую на выполнение, идеальную для трассируемости и управления проектами:

```json
{
  "floworks_version": "2.1.0",
  "author": "María Gómez",
  "description": "Análisis de vibraciones en motor trifásico",
  "created": "2026-05-10T10:30:00Z",
  "tags": ["ingeniería", "vibraciones", "FFT", "multicanal"]
}
```

## 🔄 Процесс сохранения и загрузки

FloWorks реализует надёжный механизм для гарантии целостности данных:

1. **Сохранение:**
   - Обходится граф и узлы сериализуются через `SerializableMixin`.
   - Массивы извлекаются в `data/` и ссылаются в JSON с префиксом `__npy__:`.
   - Всё упаковывается в ZIP с расширением `.sflow`.
2. **Безпасная загрузка:**
   - Создаётся **временный резерв в памяти** текущей диаграммы.
   - Извлекается и парсится новый `.sflow`.
   - Если происходит любая ошибка (неверный JSON, отсутствующие узлы, повреждение `.npy`), **резерв автоматически восстанавливается** без потери работы.
3. **Специальный ScriptNode:**
   - Сохраняет `script`, `params`, `dynamic_inputs`, `dynamic_outputs`, `persist` и `python_path`.
   - При загрузке перекомпилирует код, восстанавливает динамические порты и автоматически восстанавливает состояние `persist`.
4. **StickyNotes и DPI:**
   - Координаты и размеры нормализуются к **96 dpi** при сохранении.
   - При загрузке масштабируются к DPI текущего монитора, гарантируя визуальную согласованност между разными разрешениями.

## 🛠️ Внешнее использование и автоматизация

Формат `.sflow` разработан для прозрачности и программной обработки. Вы можете читать или генерировать его из внешних скриптов:

=== "🐍 Python (Чтение)"
    ```python
    import zipfile
    import json
    import numpy as np

    with zipfile.ZipFile("mi-flujo.sflow") as z:
        graph = json.loads(z.read("diagram.json"))
        if "metadata.json" in z.namelist():
            meta = json.loads(z.read("metadata.json"))

        datos_n1 = np.load(z.open("data/node_1.npy"))
        print(f"Nodos: {len(graph['nodes'])}")
        print(f"Datos: {datos_n1.shape}")
    ```

=== "📤 Python (Создание)"
    ```python
    import zipfile
    import json
    import numpy as np

    graph = {
        "nodes": [{"id": "gen", "type": "GeneratorNode", "pos": [100, 100], "params": {}}],
        "connections": [],
        "viewport": {"x": 0, "y": 0, "scale": 1.0}
    }

    with zipfile.ZipFile("nuevo.sflow", "w", zipfile.ZIP_DEFLATED) as z:
        z.writestr("diagram.json", json.dumps(graph, indent=2))
        z.writestr("data/gen.npy", np.array([1.0, 2.0, 3.0]))
    ```

## 🔮 Совместимость и будущая расширяемость

Формат `.sflow` следует принципам **расширяемого и обратно совместимого дизайна**:

- ✅ **Новые разделы:** Будущие версии могут добавлять папки, такие как `thumbnails/`, `logs/` или `plugins/`, не ломая старые загрузчики.
- ✅ **Опциональные поля:** Парсер игнорирует неизвестные ключи в `diagram.json`, позволяя добавлять экспериментальные метаднные.
- ✅ **Версионирование:** Пол `floworks_version` в `metadata.json` позволяет приложению применять автоматические миграции, если формат эволюционирует.

!!! warning "Золотое правило"
    Никогда не изменяйте `diagram.json` вручную, пока приложение открыто. Система зависит от согласованности между топологией, массивами и состоянием вида. Всегда используйте нативные потоки сохранения/загрузки.
