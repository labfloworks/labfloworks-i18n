# 🧪 Интерактивное руководство по консоли FloWorks

Добро пожаловать в экспериментальную лабораторию FloWorks. Этот раздел предназначен для более продвинутых пользователей: это терминал **Python** для управления всем, что связано с холстом, то есть узлами и их соединенями, последовательно и построчно. Это терминал, связанный с программой, который может управлять ею и определять поведение или рутины для удобства более требовательных пользователей.

Это руководство покажет вам **пошагово**, как управлять и анализировать ваши блок-схемы, не прикасаясь к мыши. Кждый пример был проверен в интерактивной консоли и отражает реальную структуру данных программы.

---

## 1. Изучение местности

Консоль внедряет три глобальных объекта: `app` (главное окно), `graph` (сцена/диаграмма) и `selected_node` (узел, выбранный в данный момент на холсте). Все команды исходят от этих трёх.

### Просмотр всех узлов

```python
>>> graph.nodes
```

**Пример вывода:**
```
Узлы на сцене:
  [0] Расширенный генератор сигналов (тип: SignalSourceNode, категория: Sources)
  [1] FFT (тип: FFTNode, категория: Processing)
```

Индекс в скобках (`[0]`, `[1]`) — это ваш основной способ доступа к узлу. Порядок соответствует созданию на холсте.

#### Альтернатива: подсчёт узлов или фильтрация по типу

```python
>>> len(graph.nodes)
>>> [n for n in graph.nodes if 'FFT' in type(n).__name__]
```

### Просмотр всех соединений

```python
>>> graph.connections
```

**Пример вывода:**
```
Соединения на сцене:
  [0] Расширенный генератор сигналов (out) → FFT (input)
```

Вывод показывает имя исходного узла, выходной порт, стрелку, целевой узел и входной порт. Если соединение не отображается, поток не сможет выполниться.

#### Альтернатива: просмотр соединений одного узла

```python
>>> selected_node.connectors
```

### Просмотр выбранного узла

Щёлкните узел на холсте, а затем выполните:

```python
>>> selected_node
```

**Пример вывода:**
```
Узел: FFT
  Тип: FFTNode
  Категория: Processing
  Порты: ['input', 'output', 'magnitude', 'phase']
```

> **💡 Примечание:** Если ни один узел не выбран, `selected_node` равен `None`. Выбор узла также автоматически обновляет боковую таблицу параметров.

#### Альтернатива: выбор узла по коду

```python
>>> graph.nodes[0].setSelected(True)
>>> app.console.update_namespace(selected_node=graph.nodes[0])
```

## 2. Управление узлами и соединениями без мыши

### Создание нового узла

Вы должны знать точное имя класса узла (так же, как в каталоге). Аргументы: `(тип, x, y)`.

```python
>>> graph.add_catalog_node('SumNode', 300, 200)
```

Узел появится на холсте в координатах (300, 200). Если вы не знаете точное имя, выведите список категорий (см. раздел 7).

#### Альтернатива: создание нескольких узлов сразу

```python
>>> for i, tipo in enumerate(['SignalSourceNode', 'FFTNode', 'OscilloscopeNode']):
...     graph.add_catalog_node(tipo, 100 + i*200, 300)
```

### Ручное соединение узлов

Синтаксис: `graph.connect_nodes(источник, назначение, 'выходной_порт', 'входной_порт')`. Порты зависят от каждого узла; никогда н предполагайте их названия.

```python
>>> graph.connect_nodes(graph.nodes[0], graph.nodes[2], 'output', 'port_a')
```

> **💡 Примечание:** Всегда проверяйте `graph.nodes[N].PORTS` перед подключением. У узла FFT есть `'input'` и `'magnitude'`; у генератора — `'output'`.

#### Альтернатива: подключение к порту по умолчанию

Если вы не знаете точное имя входного порта, некоторые узлы принимают `None` для использования первого доступного:

```python
>>> graph.connect_nodes(graph.nodes[0], graph.nodes[2], 'output', None)
```

### Удаление узла

```python
>>> graph.remove_node(graph.nodes[2])
```

Удаляет узел и все связанные с ним соединения. Индексы `graph.nodes` перестраиваются, поэтому не храните старые ссылки.

#### Альтернатива: удаление всех узлов категории

```python
>>> for n in list(graph.nodes):
...     if n.META.get('category') == 'Processing':
...         graph.remove_node(n)
```

### Просмотр портов узла

```python
>>> graph.nodes[1].PORTS
```

**Пример вывода:**
```
{'input': ('left', 0.5), 'output': ('right', 0.25), 'magnitude': ('right', 0.5), 'phase': ('right', 0.75)}
```

Ключ — это имя порта (строка). Значение — кортеж с визуальной позицией. Для подключения вас интересуют только ключи.

#### Альтернатива: просмотр портов в виде простого списка

```python
>>> list(graph.nodes[1].PORTS.keys())
```

## 3. Выполнение потока и просмотр результатов

### Выполнение всего графа

```python
>>> graph.execute_flow()
```

Этот метод принадлежит диаграмме (`graph`), а не главному окну. Он проходит по всем узлам в топологическом порядке, выполняет каждый и кэширует результаты. Ничего не возвращает; данные хранятся внутри.

#### Альтернатива: принудительный расчёт определённой ветви

```python
>>> result = graph.get_node_branch_value(graph.nodes[1])
```

Это пересчитывает всё дерево выше указанного узла и возвращает результат напрямую, не изменяя глобальный кэш.

### Просмотр кэшированных данных узла

Если вам нужен доступ к обработанным данным определённого узла, вы можете сделать это двумя способами:

#### Прямой способ (по объекту)
```python
>>> graph.node_values[graph.nodes[1]]
```

**Пример вывода:**
```
{'output': None, 'magnitude': (array([0., 78.125, ...]), array([0.0013, 0.0183, ...])), 'phase': (array([0., 78.125, ...]), array([0., 0.687, ...]))}
```

> **⚠️ Предупреждение:** Этот способ может завершиться ошибкой `KeyError`, если порядок узлов на сцене изменился (например, при удалении или добавлении узлов) или если экземпляр объекта не совпадает точно с сохранённым ключом словаря.

#### Альтернативный способ (по позиции)
```python
>>> list(graph.node_values.values())[1]
```

Этот способ **более стабильный**, потому что не зависит от точной идентичности объекта. Порядок значений следует последовательности, в которой узлы были выполнены во время последнего `graph.execute_flow()`. Индекс `[1]` соответствует второму узлу в этой последовательности.

> **💡 Примечание:** Если вы хотите увидеть индекс каждого узла в порядке выполнения, можно использовать:
> ```python
> >>> list(graph.node_values.keys())
> ```

> **⚠️ Внимание:** `graph.node_values` не всегда возвращает массив напрямую. Для обрабатывающих узлов (FFT, фильтры и т.д.) возвращается **словарь**, где кажды ключ — это выходной порт. Для узлов-источников возвращается кортеж `(x, y)`.

#### Альтернатива: просмотр данных всех узлов в одной строке
```python
>>> {n.name: type(v).__name__ for n, v in graph.node_values.items()}
```

### Доступ к оси Y узла-источника

Генераторы узлов (SignalSourceNode, FileInputNode и т.д.) при выполнении возвращают кортеж `(время, сигнал)`. Чтобы получить только ось Y:

```python
>>> result = graph.get_node_branch_value(graph.nodes[0])
>>> y = result[1]
>>> y.max()
```

**Пример вывода:**
```
Scalar NumPy (float64): 1.0
```

#### Альтернатива: получение оси X (время)

```python
>>> x = result[0]
>>> x[:5]
```

### Присваивания в Python: жизненно важная деталь

В Python присваивания (`=`) — это **оераторы**, а не выражения. Консоль ничего не выводит после `x, y = ...`, потому что нет возвращаемого значения.

```python
>>> x, y = graph.get_node_branch_value(graph.nodes[0])
```

Чтобы проверить, что всё сработало, оцените переменную в следующей строке:

```python
>>> x
>>> y.shape
```

Или используйте `;` для объединения выражения в той же строке:

```python
>>> x, y = graph.get_node_branch_value(graph.nodes[0]); y.max()
```

Или используйте явный `print()`:

```python
>>> x, y = graph.get_node_branch_value(graph.nodes[0]); print(y.max())
```

## 4. Рисование на главном графике

### Очистка графика

```python
>>> app.plot_widget.clear_plot()
```

#### Альтернатива: очистка и немедленное перерисовывание

```python
>>> app.plot_widget.clear_plot(); graph.execute_flow()
```

### Рисование произвольного сигнала из консоли

Вы можете создавать массивы с помощью NumPy и отправлять их прямо в виджет графика, не проходя через какой-либо узел.

```python
>>> import numpy as np
>>> x = np.linspace(0, 1, 1000)
>>> y = np.sin(2 * np.pi * 10 * x)
>>> app.plot_widget.plot_waveform(x, y)
```

#### Альтернатива: рисование суммы синусоид

```python
>>> y = np.sin(2*np.pi*5*x) + 0.3*np.sin(2*np.pi*50*x) + 0.1*np.random.randn(1000)
>>> app.plot_widget.plot_waveform(x, y)
```

### Рисование результата узла-источника

Поскольку узел-источник возвращает `(x, y)`, вы можете распаковать напрямую:

```python
>>> x, y = graph.get_node_branch_value(graph.nodes[0])
>>> app.plot_widget.plot_waveform(x, y)
```

### Рисование результата узла FFT (несколько портов)

Узлы с несколькими выходами (FFT, анализ время-частота и т.д.) не возвращают простой кортеж. Они возвращают `dict`, где каждый ключ — это выходной порт.

```python
>>> result = graph.get_node_branch_value(graph.nodes[1])
>>> result.keys()
```

**Пример вывода:**
```
dict_keys(['output', 'magnitude', 'phase'])
```

Обратите внимание, что `'output'` может быть `None`, если у узла нет общего порта. Полезные выходы — `'magnitude'` и `'phase'`, которые в свою очередь являются кортежами `(частоты, значения)`:

```python
>>> f, mag = result['magnitude']
>>> app.plot_widget.plot_waveform(f, mag)
```

#### Альтернатива: рисование фазы вместо амплитуды

```python
>>> f, phase = result['phase']
>>> app.plot_widget.plot_waveform(f, phase)
```

#### Альтернатива: наложение двух сигналов

```python
>>> x1, y1 = graph.get_node_branch_value(graph.nodes[0])
>>> app.plot_widget.plot_waveform(x1, y1)
>>> x2, y2 = graph.get_node_branch_value(graph.nodes[2])  # другой узел
>>> app.plot_widget.plot_waveform(x2, y2)  # накладываеся
```

> **💡 Примечание:** Если вы попытаетесь выполнить `x, y = result` с dict, Python выдаст `ValueError: too many values to unpack`. Всегда проверяйте с помощью `type(result)` и `result.keys()` перед распаковкой.

## 5. Изменение приложения на лету

### Обновление боковой таблицы параметров

Если вы изменили параметр по коду и хотите, чтобы боковая таблица отражала изменение:

```python
>>> app.workspace_table.populate()
```

Этот метод не принимает аргументов. Он обновляет таблицу текущими значениями выбранного узла.

#### Альтернатива: принудительный выбор другого узла и обновление

```python
>>> graph.nodes[1].setSelected(True)
>>> app.workspace_table.populate()
```

### Добавление узла из панели инструментов

```python
>>> app.add_node('SignalSourceNode')
```

Это эквивалентно нажатию кнопки "+" на панели инструментов. Узел размещается в предопределённой позиции на холсте.

### Изменение заголовка окна

`setWindowTitle` — это нативный метод Qt. Он работает, но имейте в виду, что приложение может иметь таймер или событие, вызывающее `update_title()`, который автоматически перезапишет его.

```python
>>> app.setWindowTitle('Моя лаборатория сигналов')
>>> app.windowTitle()
```

Чтобы восстановить "официальный" заголовок, который приложение вычисляет из своего внутреннего состояния (имя проекта, файл и т.д.):

```python
>>> app.update_title()
```

#### Альтернатива: заголовок с именем проекта

```python
>>> app.setWindowTitle(f'FloWorks — {graph.nodes[0].name}')
```

## 6. Навигация и производительность в консоли

Консоль — это не просто `print()`. У неё есть история, автодополнение и многострочные блоки.

| Клавиша / Команда           | Действие                                                         |
|---------------------------|----------------------------------------------------------------|
| `↑` / `↓`                 | Навигация по истории выполненных команд                |
| `Tab`                     | Автодополнение переменных, атрибутов и методов пространства имён     |
| `Ctrl + L`                | Очистка всей консоли (удаляет текст, не состояние Python)  |
| `if`, `for`, `def`, `class` | Приглашение меняется с `>>>` на `...` для многострочных блоков     |
| `Ctrl+C` (в выделении)   | Копирование текста из консоли                                     |
| `Ctrl+A`                  | Выделение всего содержимого                                  |

> **💡 Примечание:** Автодополнение использует `rlcompleter` и распознаёт всё внедрённое пространство имён (`app`, `graph`, `selected_node`) плюс любые переменные, которые вы определите в сеансе.

## 7. Продвинутые рецепты

### Изменение внутреннего параметра узла

Параметры узлов — это не плоские атрибуты. Они вложены в словарь `params`, который в свою очередь имеет подразделы, такие как `'preset'`, `'formula'` или `'advanced'`. Никогда не делайте `node.amplitude = 3.0`; это создаёт новый атрибут в объекте, но не изменяет реальный параметр.

#### Случай A: изменение предустановки (синус, прямоугольная и т.д.)

```python
>>> selected_node.params['mode'] = 'preset'
>>> selected_node.params['preset']['type'] = 'SINE'
>>> selected_node.params['preset']['amplitude'] = 2.0
>>> selected_node.params['preset']['frequency'] = 1000.0
>>> selected_node._generate_signal()
>>> graph.execute_flow()
```

#### Случай B: использование пользовательской формулы

```python
>>> selected_node.params['mode'] = 'formula'
>>> selected_node.params['formula']['expr'] = '2 * sin(2*pi*1000*t)'
>>> selected_node.params['formula']['vars'] = {'amp': 2.0, 'freq': 1000.0, 'offset': 0.0}
>>> selected_node._generate_signal()
>>> graph.execute_flow()
```

Выражение использует `t` как переменную времени. Значения в `vars` — это символы, которые вы можете использовать в формуле. Если вы опустите `vars`, узел будет использовать значения по умолчанию, и формула может не отразить изменение.

#### Случай C: изменение продвинутых параметров (частота дискретизации, длительность)

```python
>>> selected_node.params['advanced']['duration'] = 0.02
>>> selected_node.params['advanced']['sample_rate'] = 44100
>>> selected_node._generate_signal()
>>> graph.execute_flow()
```

#### Случай D: изменение параметра негенераторного узла (например, FFT)

```python
>>> selected_node.params['window'] = 'hann'
>>> graph.execute_flow()
```

> **💡 Примечание:** `getattr(obj, '_generate_signal', lambda: None)()` — это безопасный шаблон: если метод существует (генераторы), он вызывает его; если нет, ничего не делает и не выдаёт ошибку. Для обрабатывающих узлов достаточно только `graph.execute_flow()`.

### Список всех доступных категорий узлов

Импорт загружает каталог, но не отображает его автоматически. Помните, что в Python успешный импорт ничего не выводит; вы должны оценить объект.

```python
>>> from nodes.node_catalog import NODE_CATEGORIES
>>> NODE_CATEGORIES
```

Для читаемого резюме:

```python
>>> for cat, nodos in NODE_CATEGORIES.items():
...     print(f"{cat}: {len(nodos)} узлов")
```

#### Альтернатива: список имён узлов по категориям

```python
>>> {cat: [n.__name__ for n in nodos] for cat, nodos in NODE_CATEGORIES.items()}
```

### Просмотр справки по любому методу

```python
>>> help(graph.connect_nodes)
```

Docstring отображается прямо в консоли. Это полезно для обнаружения ожидаемых аргументов метода без открытия исходного кода.

#### Альтернатива: просмотр отфильтрованных атрибутов

```python
>>> [m for m in dir(graph) if 'connect' in m.lower()]
>>> [m for m in dir(selected_node) if 'param' in m.lower()]
```

## 8. Что делать, если что-то пойдёт не так?

- **Ошибка красным в консоли:** трассировка отображается полностью. Приложение не закрывается; вы можете исправить команду и попробовать снова.
- **Интерфейс завис:** вероятно, вы написали бесконечный цикл. Консоль выполняется в отдельном потоке, но если цикл затрагивает GUI-поток, перезапустите приложение.
- **Неожиданный `None`:** если узел возвращает `None` вместо данных, проверьте, подключён ли он выше по течению (`graph.connections`), и выполнен ли поток (`graph.execute_flow()`).
- **`ValueError: too many values to unpack`:** вы пытаетесь распаковать dict как кортеж. Используйте сначала `result.keys()`.
- **`ValueError: not enough values to unpack`:** вы ожидаете 2 значения, но узел возвращает 1 (dict) или 3 (спектрограмма). Проверяйте с помощью `type(result)` перед распаковкой.
- **`AttributeError`:** у объекта нет этого атрибута. Используйте `dir(obj)` или `[a for a in dir(obj) if 'слово' in a.lower()]` для обнаружения правильного имени.
- **Ничего не происходит при выполнении:** проверьте, что есть хотя бы один узел-источник, подключённый к цепи, и что `graph.execute_flow()` был вызван. Обрабатывающие узлы не генерируют данные сами по себе.
- **График не меняется:** убедитесь, что вы вызвали `graph.execute_flow()` после изменения параметров. Простое изменение `params` не пересчитывает автоматически.
