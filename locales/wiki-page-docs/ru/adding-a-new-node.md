## 1. Введение в архитектуру

FloWorks построен на PySide6 и использует модель соединяемых узлов, представляющих поток обработки сигналов.

---

## 2. Использование шаблона `template_node.py`

Для упрощения создания новых узлов предоставляется файл `nodes/template_node.py`. Этот шаблон включает:
- Полную поддержку интернационализации (подключение к `languageChanged`, метод `update_language`).
- Полную поддержку тем (метод `update_theme`).
- Встроенную справку в формате HTML из трёх разделов.
- Управление несколькими настраиваемыми портами ввода/вывода.
- Несколько выходов с помощью `get_output_for_port`.
- Визуализацию на графике через `get_display_signal`.
- Переводимое контекстное меню.

Рекомендуется всегда начинать разработку нового узла с этого шаблона.

---

## 3. Пошаговое создание пользовательского узла

### 3.1. Копирование и переименование шаблона
1. Скопируйте `nodes/template_node.py` под именем вашего нового узла, например `nodes/mi_nodo.py`.
2. Переименуйте класс из `TemplateNode` в описательное имя, например `MiNodoNode`.
3. При необходимости откорректируйте импорты.

### 3.2. Определение портов и меток
!!! warning "Важно: совпадение имён"
    Имена портов в `PORTS`, `PORT_LABELS` и ключи словаря, возвращаемого `execute_program`, должны быть **точно одинаковыми** (включая регистр). Шаблон теперь включает сопоставление псевдонимов (`'data_in'` → первый левый порт) для болшей надёжности.

Отредактируйте словарь `PORTS` в верхней части файла. Каждая запись имеет формат:
```python
"имя_порта": ("сторона", доля)
```
- **Возможные стороны:** `"left"`, `"right"`, `"top"`, `"bottom"`.
- **Доля:** значение от `0.0` до `1.0`, указывающее положение вдоль стороны.

**Пример для узла с одним входом и двумя выходами:**
```python
PORTS = {
    "input":     ("left",  0.5),
    "magnitude": ("right", 0.35),
    "phase":     ("right", 0.65),
}
```
Словарь `PORT_LABELS` содержит текст, который будет отображаться рядом с каждым портом. Рекомендуется использовать ключи перевода вместо фиксированного текста (см. раздел Интернационализация).

### 3.3. Реализация логики обработки
Ключевой метод — `execute_program(self, input_data)`. Этот метод вызывается движком потоков, когда узел получает данные.

**`input_data` может быть:**
- `None`, если нет входных данных.
- Кортеж `(x, y)` для временных сигналов.
- Одномерный массив.
- Словарь `{имя_порта: данные}` для узлов с несколькими входами.

**Возвращаемое значение:**
- Для узлов с одним выходом возвращайте данные напрямую (например, кортеж `(x, y)`).
- Для узлов с несколькими выходами возвращайте словарь, ключи которого совпадают с именами выходных портов, определёнными в `PORTS`.

```python
def execute_program(self, input_data):
    # Обработать input_data и сгенерировть результаты
    resultado_magnitud = (freq, mag)
    resultado_fase = (freq, phase)
    return {
        "magnitude": resultado_magnitud,
        "phase": resultado_fase
    }
```

!!! tip "Примечание об общих именах портов"
    Движок потоков может иногда передавать словарь с ключами, такими как `'data_in'`, вместо реального имени порта (особенно если пользователь не щёлкнул точно по кружку). Шаблон уже включает код для обработки этого случая:
    ```python
    if isinstance(input_data, dict):
        if 'data_in' in input_data:
            input_data = input_data['data_in']
    ```
    Это предотвращает сбой узла из-за неточного соединения.

Шаблон уже содержит закомментированный пример. Кроме того, реализуйте `get_output_for_port(self, port_name)`, чтобы движок мог направлять каждый выход:
```python
def get_output_for_port(self, port_name):
    return self.output_data.get(port_name)
```

### 3.4. Настройка внешнего вида (опционально)
Метод `paint()` рисует фон, заголовок, состояние и любой дополнительный текст. Вы можете изменить:
- Цвета (автоматически обновляются через `update_theme`).
- Текст состояния (с использованием атрибута `self._status`).
- Сводную информацию (например, пиковое значение амплитуды).

Шаблон содержит базовый пример.

### 3.5. Добавление настраиваемых параметров (опционально)
Если вашему узлу требуются параметры, настраиваемые пользователем (например, размер окна, частота среза), вы можете:
1. Добавить атрибуты в `__init__` (например, `self.window_size = 512`).
2. Создать диалог настройки (наследуйте `QDialog`).
3. Подключить диалог в `open_config_dialog()` (метод уже присутствует в шаблоне).
4. Обновить параметры из диалога и вызвать `self.update()`.

### 3.6. Сериализация узла (сохранение / загрузка конфигураций)
Чтобы узел мог сохранять и восстанавливать свои параметры при копировании/вставке, отмене/повторе или при использовании команд Сохранить/Открыть в меню Файл, он должен наследовать примесь сериализации и объявить свои атрибуты.

1. Импортируйте примесь в свой файл:
    ```python
    from nodes.serializable import SerializableMixin
    ```
2. Измените наследование класса, чтобы включить её перед `QGraphicsObject`:
    ```python
    class MiNodoNode(SerializableMixin, QGraphicsObject):
    ```
3. Определите список `SERIALISABLE` на уровне класса с именами атрибутов, которые хотите сохранять. Поддерживаются только простые типы (`int`, `float`, `str`, `bool`), списки, словари или массивы NumPy (последние автоматически хранятся как файлы `.npy` внутри `.sflow`).
    ```python
    class MiNodoNode(SerializableMixin, QGraphicsObject):
        SERIALISABLE = ['frecuencia', 'amplitud', 'configuracion']
    ```
4. Убедитесь, что эти атрибуты инициализируются в `__init__`:
    ```python
    self.frecuencia = 1000.0
    self.amplitud = 1.0
    self.configuracion = {'tipo': 'seno', 'fase': 0}
    ```

При этом вам не нужно писать методы `serialize`/`deserialize`; примесь автоматически сохраняет и восстанавливает значения.

Если узлу требуется дополнительная логика при загузке (например, повторное подключение аппаратного устройства), вы можете переопределить `deserialize`, сначала вызвав родительский метод:
```python
def deserialize(self, data):
    super().deserialize(data)   # восстанавливает атрибуты из SERIALISABLE
    self._iniciar_dispositivo()
```

## 5. Интернационализация (i18n)

Все видимые тексты должны быть переводимы с помощью `tr("ключ", default="...")`. Шаблон уже реализует это. Вам нужно добавить соответствующие ключи в файлы JSON внутри `locales/`.

**Рекомендуемая структура:**
```json
{
   "nodes": {
     "mi_nodo": {
       "title": "Mi Nodo",
       "tooltip": "Descripción emergente",
       "ports": {
         "input": "Entrada",
         "output1": "Salida 1",
         "output2": "Salida 2"
      },
       "status": {
         "no_data": "Sin datos",
         "ready": "Listo"
      },
       "menu": {
         "show_output": "Mostrar salida",
         "configure": "Configurar..."
      },
       "help_title": "Ayuda - Mi Nodo",
       "help_html": "<h3>🎛️ Filter Node</h3>\n<p>Applies a <b>digital filter</b>...</p>"
    }
  },
   "toolbar": {
     "add_mi_nodo": "Mi Nodo"
  }
}
```

HTML-справка следует формату из трёх разделов, общему для всех узлов (описание конкретного узла + "Как мыслить в системе" + "Сочетания клавиш и хитрости"). Шаблон уже включает структуру в `get_help_text()`.

## 6. Визуальные темы

Метод `update_theme(self, theme)` получает словарь с цветами, определёнными текущей темой. Шаблон автоматически обновляет:
- Фон узла (`node_normal_bg`)
- Границу (`node_selected_border`)
- Цвет заголовка и текста (`node_normal_text`)
- Цвета портов (`port_circle`, `port_outline`, `port_inline`, `port_text`)

Убедитесь, что в `MainWindow` (или `ThemeUpdater`) вызывается `node.update_theme()` для каждого узла при смене темы.

## 7. Контрольный список и устранение неполадок

### ✅ Контрольный список
- [ ] Узел корректно создаётся из панели инструментов.
- [ ] Порты отображаются в ожидаемых поициях и доступн для соединений (`Ctrl+щелчок`).
- [ ] При получении входных данных вызывается `execute_program` и сигнал обрабатывается.
- [ ] Выходы корректно распространяются на подключённые узлы.
- [ ] Контекстное меню позволяет изменить канал визуализации (если есть несколько выходов).
- [ ] При щелчке по узлу выбранный сигнал отображается на виджете графика.
- [ ] Двойной щелчок открывает справку в надлежащем формате.
- [ ] Язык меняется корректно (тексты заголовков, портов, меню).
- [ ] Тема меняется корректно (цвета узла и портов).
- [ ] Копирование/вставка работает без ошибок.

!!! tip "Точное соединение портов"
    При соединении узлов убедитесь, что щёлкаете точно по кружку целевого порта. Если щёлкнуть по телу узла, система использует общее имя (`'data_in'`). Шаблон теперь допускает такие имена, но хорошей практикой является прямое соединение с кружком, чтобы гарантировать правильную маршрутизацию нескольких выходов.

### 🐛 Распространённые проблемы

| Симптом | Возможная причина | Решение |
|---------|-------------------|---------|
| Стрелка соединения не закрепляется у порта. | У кружка порта нет `setData(0, port_name)` или `get_port_scene_pos` не реализован. | Проверьте, что в `_create_ports` выполняется `circle.setData(0, port_name)` и что `get_port_scene_pos` использует это имя. |
| Выходы не доходят до подключённых узлов. | `execute_program` не возвращает словарь (для нескольких выходов) или `get_output_for_port` не реализован. | Убедитесь, что `execute_program` возвращает `{имя_порта: данные}` и что `get_output_for_port` возвращает соответствующее значение. |
| При щелчке по узлу ничего не отображается на графике. | `get_display_signal` не возвращает корректный кортеж `(x, y)` или `display_channel` не совпадает с существующим выходом. | Проверьте, что `get_display_signal` использует выбранный канал и что данные являются массивами NumPy. |
| Тексты не обновляются при смене языка. | Не подключён сигнал `languageChanged` или `update_language` не обновляет элементы. | Проверьте подключение в `__init__`: `language_manager.languageChanged.connect(self.update_language)`. |
| Тема не применяется. | Не вызывается `update_theme` при создании узла или при смене темы. | В `MainWindow`, после создания узла, вызовите `node.update_theme(self.theme_manager.current_theme())`. |
| Стрелка указывает в центр узла. | Щелчок выполнен по телу вместо кружка, или имя не совпадает с `PORTS`. | Щёлкайте прямо по кружку. Проверьте, что `get_port_scene_pos` содержит сопоставление псевдонимов. |
| `NameError: name 'self' is not defined` при импорте. | Атрибуты экземпляра объявлены вне `__init__`. | Все атрибуты, такие как `self.mi_parametro`, должны определяться внутри `__init__`. |
| Параметры теряются при копировании/открытии `.sflow`. | Узел не наследует `SerializableMixin` или не определён `SERIALISABLE`. | Реализуйте шаг 3.6 данного руководства. |
