# 📄 `.sflow` फ़ाइल स्वरूप

`.sflow` स्वरूप **FloWorks** का मूल आदान-प्रदान और दृढ़ता मानक है। यह एक पूर्ण वर्कफ़्लो को एकल फ़ाइल में पैकेज करने की अनुमति देता है जिसमें ग्राफ़ टोोलॉजी, नोड पैरामीटर, संसाधित डेटा और स्टिकी नोट्स शामिल हैं, जिससे साझाकरण, संग्रहण या स्पष्ट रूप से प्रयोगों को पुन: उत्पन्न करना आसान हो जाता है।

---

## 📦 `.sflow` फ़ाइल क्या है?

`.sflow` फ़ाइल, सारांश में, एक **नाम बदली हुई ZIP फ़ाइल** है। इसका विस्तार `.zip` मं बदलकर, आप इसकी सामग्री को किसी भी फ़ाइल प्रबंधक या कमांड-लाइन उपकरण के साथ निरीक्षण कर सकते हैं।

इसकी न्यूनतम आंतरिक संरचना इस प्रकार है:

| घटक | विवरण |
|------------|-------------|
| `diagram.json` | मुख्य मैनिफ़ेस्ट: नोड्स, कनेक्शन, दृश्य, स्टिकी नोट्स और क्रमबद्धता मेटाडेटा को परिभाषित करता है। |
| `data/` | प्रत्येक नोड के डेटा वाली फ़ोल्डर `.npy` स्वरूप में (NumPy बाइनरी सरणियाँ)। |
| `metadata.json` *(वैकल्पिक)* | पूरक जानकारी: लेखक, FloWorks संस्करण, विवरण और टैग। |

=== "🌳 दृश्य संरचना"
    ```text
    mi-flujo.sflow
    ├── diagram.json
    ├── metadata.json
    └── data/
        ├── node_1.npy
        ├── node_2.npy
        └── script_state.npy (वैकल्पिक, ScriptNode persist के लिए)
    ```

---

## 🧩 `diagram.json` – फ्लो का हृदय

यह JSON फ़ाइल संपूर्ण टोपोलॉजी, कैनवास पर तत्वों की स्थिति और सहेजने के समय दृश्य की स्थिति का वर्णन करती है।

### न्यूनतम उदाहरण
```json
{
  "nodes": [
    {
      "id": "n1",
      "type": "OscilloscopeNode",
      "pos": [150, 200],
      "params": { "channel": "primary", "simulation": false }
    },
    {
      "id": "n2",
      "type": "GraphExporterNode",
      "pos": [450, 200],
      "params": { "theme": "dark", "export_format": "png" }
    }
  ],
  "connections": [
    {
      "from": "n1",
      "to": "n2",
      "from_port": "out",
      "to_port": "data_in"
    }
  ],
  "viewport": { "x": 0, "y": 0, "scale": 1.0 },
  "stickers": [
    { "x": 600, "y": 100, "width": 200, "height": 150, "text": "Revisar umbral", "user_modified": true }
  ]
}
```

### मुख्य क्षेत्र
| क्षेत्र | प्रकार | विवरण |
|-------|------|-------------|
| `nodes` | `Array` | `{id, type, pos, params}` वस्तुओं की सूची। `type` `node_registry.py` से मेल खाना चाहिए। |
| `connections` | `Array` | कनेक्शन `{from, to, from_port, to_port}` की सूची। पोर्ट अनुक्रमणिका नहीं, स्ट्रिंग हैं। |
| `viewport` | `Object` | कैनवास की स्थिति और ज़ूम को ठीक से पुनर्स्ापित करने के लिए `(x, y, scale)`। |
| `stickers` | `Array` | 96 dpi पर सामान्यीकृत निर्देशांकों के साथ क्रमबद्ध स्टिकी नोट्स। |

!!! tip "नोड्स की क्रमबद्धता"
    प्रत्येक नोड के विशिष्ट पैरामीटर `SerializableMixin` के माध्यम से प्रबंधित किए जाते हैं। केवल `SERIALISABLE = [...]` में घोषित गुण सहेजे जाते हैं। सिस्टम में पंजीकृत नहीं नोड्स लोड के दौरान स्वचालित रूप से छोड़ दिए जाते हैं।

## 💾 `data/` – संसाधित डेटा और NumPy सरणियाँ

जब एक फ्लो निष्पादित होता है, नोड्स अपने परिणामों को इस फ़ोल्डर के अंदर `.npy` फ़ाइलों में संग्रहीत कर सकते हैं।

- फ़ाइल नाम आमतौर पर नोड के `id` या आंतरिक संदर्भों से मेल खाता है।
- सरणियाँ NumPy बाइनरी स्वरूप में संग्रहीत होती हैं, **मूल विमामिता को कड़ाई से संरक्षित** करती हैं (1D, 2D, 3D, आदि)। इंजन कभी भी `flatten()` लागू नहीं करता।
- `diagram.json` में, डेटा `__npy__:` उपसर्ग के साथ संदर्भित होता है:
  ```json
  "params": { "cached_output": "__npy__:node_2.npy" }
  ```
- यदि कोई नोड डेटा उत्पन्न नहीं करता है या उन्हें दृढ़ करने के लिए कॉन्फ़िगर नहीं किया गया है, तो संबंधित फ़ाइल को छोड़ा जा सकता है।

??? note "बाहरी संगतता"
    `.npy` फ़ाइलें Python पारिस्थितिकी तंत्र में सार्वभौमिक हैं। आप उन्हें FloWorks के बाहर पढ़ सकते हैं:
    ```python
    import numpy as np
    datos = np.load("data/node_1.npy")
    print(datos.shape)
    ```

## 🏷️ `metadata.json` (वैकल्पिक)

निष्पादन को प्रभावित न करने वाला वर्णनात्मक जानकारी शामिल है, अनुवर्तन और परियोजना प्रबंधन के लिए आदर्श:

```json
{
  "floworks_version": "2.1.0",
  "author": "María Gómez",
  "description": "Análisis de vibraciones en motor trifásico",
  "created": "2026-05-10T10:30:00Z",
  "tags": ["ingeniería", "vibraciones", "FFT", "multicanal"]
}
```

## 🔄 सहेजने और लोड करने की प्रक्रिया

FloWorks डेटा अखंडता की गारंटी के लिए एक मज़बूत तंत्र लागू करता है:

1. **सहेजना:**
   - ग्राफ़ को पार किया जाता है और नोड्स `SerializableMixin` के माध्यम से क्रमबद्ध होते हैं।
   - सरणियाँ `data/` में निकाली जाती हैं और JSON में `__npy__:` उपसर्ग के साथ संदर्भित होती हैं।
   - सब कुछ `.sflow` विस्तार के साथ एक ZIP में पैकेज किया जाता है।
2. **सुरक्षित लोडिंग:**
   - वर्तमान आरेख का एक **अस्थायी मेमोरी बैकअप** बनाया जाता है।
   - नया `.sflow` निकाला और पार्स किया जाता है।
   - यदि कोई त्रुटि होती है (अमान्य JSON, गायब नोड्स, `.npy` भ्रष्टाचार), **बैकअप स्वचालित रूप से पुनर्स्थापित** हो जाता है बिना किसी काम के नुकसान के।
3. **विशेष ScriptNode:**
   - `script`, `params`, `dynamic_inputs`, `dynamic_outputs`, `persist` और `python_path` सहेजता है।
   - लोड होने पर, कोड पुन: संकलित करता है, गतिशील पोर्ट् का पुनर्निर्माण करता है और `persist` स्थिति स्वचालित रूप से पुनर्स्थापित करता है।
4. **StickyNotes और DPI:**
   - निर्देशांक और आकार सहेजते समय **96 dpi** पर सामान्यीकृत किए जाते हैं।
   - लोड होने पर, वे वर्तमान मॉनिटर के DPI के अनुसार स्केल होते हैं, विभिन्न रिज़ॉल्यूशन के बीच दृश्य संगतता की गारंटी देते हैं।

## 🛠️ बाहरी उपयोग और स्वचालन

`.sflow` स्वरूप पारदर्शी और प्रोग्रामेटिक होने के लिए डिज़ाइन किया गया है। आप इसे बाहरी स्क्रिप्ट से पढ़ या उत्पन्न कर सकते हैं:

=== "🐍 Python (पढ़ा)"
    ```python
    import zipfile
    import json
    import numpy as np

    with zipfile.ZipFile("mi-flujo.sflow") as z:
        graph = json.loads(z.read("diagram.json"))
        if "metadata.json" in z.namelist():
            meta = json.loads(z.read("metadata.json"))

        datos_n1 = np.load(z.open("data/node_1.npy"))
        print(f"Nodos: {len(graph['nodes'])}")
        print(f"Datos: {datos_n1.shape}")
    ```

=== "📤 Python (मूल निर्माण)"
    ```python
    import zipfile
    import json
    import numpy as np

    graph = {
        "nodes": [{"id": "gen", "type": "GeneratorNode", "pos": [100, 100], "params": {}}],
        "connections": [],
        "viewport": {"x": 0, "y": 0, "scale": 1.0}
    }

    with zipfile.ZipFile("nuevo.sflow", "w", zipfile.ZIP_DEFLATED) as z:
        z.writestr("diagram.json", json.dumps(graph, indent=2))
        z.writestr("data/gen.npy", np.array([1.0, 2.0, 3.0]))
    ```

## 🔮 संगतता और भविष्य की विस्तारणीयता

`.sflow` स्वरूप **विस्तारणीय और पश्च-संगत डिज़ाइन** के सिद्धांतों का पालन करता है:

- ✅ **नए अनुभाग:** भविष्य के संस्करण `thumbnails/`, `logs/` या `plugins/` जैसी फ़ोल्डर जोड़ सकते हैं बिना पुराने लोर तोड़े।
- ✅ **वैकल्पिक क्षेत्र:** पार्सर `diagram.json` में अज्ञात कुंजियों को अनदेखा करता है, प्रयोगात्मक मेटाडेटा जोड़ने की अनुमति देता है।
- ✅ **संस्करणन:** `metadata.json` में `floworks_version` क्षेत्र एप्लिकेशन को यदि स्वरूप विकसित हो तो स्वचालित माइग्रेशन लागू करने की अनुमति देता है।

!!! warning "सुनहरा नियम"
    कभी भी एप्लिकेशन खुला होने पर `diagram.json` को मैन्युअल रूप से संशोधित न करें। सिस्टम टोपोलॉजी, सरणियों और दृश्य स्थिति के बीच संगतता पर निर्भर करता है। हमेशा मूल सहेजने/लोड करे के प्रवाह का उपयोग करें।
