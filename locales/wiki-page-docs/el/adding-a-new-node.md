## 1. Εισαγωγή στην Αρχιτεκτονική

Το FloWorks είναι χτισμένο πάνω στο PySide6 και χρησιμοποιεί ένα μοντέλο συνδεόμενων κόμβων που αναπαριστούν μια ροή επεξεργασίας σημάτων.

---

## 2. Χρήση του Προτύπου `template_node.py`

Για να διευκολυνθεί η δημιουργία νέων κόμβων, παρέχεται το αρχείο `nodes/template_node.py`. Αυτό το πρότυπο περιλαμβάνει:
- Πλήρη υποστήριξη για διεθνοποίηση (σύνδεση σε `languageChanged`, μέθοδος `update_language`).
- Πλήρη υποστήριξη για θέματα (μέθοδος `update_theme`).
- Ενσωματωμένη βοήθεια σε μορφή HTML με τρεις ενότητες.
- Διαχείριση πολλαπλών διαμορφώσιμων θυρών εισόδου/εξόδου.
- Πολλαπλές εξόδους με `get_output_for_port`.
- Οπτικοποίηση στο διάγραμμα μέσω `get_display_signal`.
- Μεταφράσιμο μενού περιβάλλοντος.

Συνιστάται πάντα να ξεκινάτε από αυτό το πρότυπο κατά την ανάπτυξη ενός νέου κόμβου.

---

## 3. Βήμα προς Βήμα: Δημιουργία Προσαρμοσμένου Κόμβου

### 3.1. Αντιγραφή και Μετονομασία του Προτύπου
1. Αντιγράψτε το `nodes/template_node.py` με το όνομα του νέου κόμβου σας, για παράδειγμα `nodes/mi_nodo.py`.
2. Μετονομάστε την κλάση από `TemplateNode` σε κάτι περιγραφικό, π.χ. `MiNodoNode`.
3. Προσαρμόστε τα imports αν χρειάζεται.

### 3.2. Ορισμός Θυρών και Ετικετών
!!! warning "Σημαντικό: Ταίριασμα Ονομάτων"
    Τα ονόματα θυρών στο `PORTS`, στο `PORT_LABELS` και τα κλειδιά του λεξικού που επιστρέφεται από το `execute_program` πρέπει να είναι **ακριβώς ίδια** (συμπεριλαμβανομένων πεζών/κεφαλαίων). Το πρότυπο περιλαμβάνει πλέον έναν χάρτη ψευδωνύμων (`'data_in'` → πρώτος αριστερός κόμβος) για μεγαλύτερη ανθεκτικότητα.

Επεξεργαστείτε το λεξικό `PORTS` στο πάνω μέρος του αρχείου. Κάθε καταχώριση έχει τη μορφή:
```python
"όνομα_θύρας": ("πλευρά", κλάσμα)
```
- **Δυνατές πλευρές:** `"left"`, `"right"`, `"top"`, `"bottom"`.
- **Κλάσμα:** τιμή μεταξύ `0.0` και `1.0` που υποδεικνύει τη θέση κατά μήκος της πλευράς.

**Παράδειγμα για κόμβο με μία είσοδο και δύο εξόδους:**
```python
PORTS = {
    "input":     ("left",  0.5),
    "magnitude": ("right", 0.35),
    "phase":     ("right", 0.65),
}
```
Το λεξικό `PORT_LABELS` περιέχει το κείμενο που θα εμφανίζεται δίπλα σε κάθε θύρα. Συνιστάται η χρήση κλειδιών μετάφρασης αντί για σταθερό κείμενο (δείτε ενότητα Διεθνοποίηση).

### 3.3. Υλοποίηση Λογικής Επεξεργασίας
Η βασική μέθοδος είναι η `execute_program(self, input_data)`. Αυτή η μέθοδος καλείται από τη μηχανή ροής όταν ο κόμβος λαμβάνει δεδομένα.

**Το `input_data` μορεί να είναι:**
- `None` αν δεν υπάρχει είσοδος.
- Μια πλειάδα `(x, y)` για χρονικά σήματα.
- Ένας πίνακας 1D.
- Ένα λεξικό `{όνομα_θύρας: δεδομένα}` σε κόμβους με πολλαπλές εισόδους.

**Τιμή επιστροφής:**
- Για κόμβους με μία έξοδο, επιστρέψτε απευθείας τα δεδομένα (π.χ. πλειάδα `(x, y)`).
- Για κόμβους με πολλαλές εξόδους, επιστρέψτε ένα λεξικό όπου τα κλειδιά ταιριάζουν με τα ονόματα των θυρών εξόδου που ορίζονται στο `PORTS`.

```python
def execute_program(self, input_data):
    # Επεξεργαστείτε το input_data και παράγετε αποτελέσματα
    αποτέλεσμα_μέτρου = (freq, mag)
    αποτέλεσμα_φάσης = (freq, phase)
    return {
        "magnitude": αποτέλεσμα_μέτρου,
        "phase": αποτέλεσμα_φάσης
    }
```

!!! tip "Σημείωση για γενικά ονόματα θυρών"
    Η μηχανή ροής μπορεί περιστασιακά να περάσει ένα λεξικό με κλειδιά όπως το `'data_in'` αντί για το πραγματικό όνομα της θύρας (ειδικά αν ο χρήστης δεν έκανε κλικ ακριβώς στον κύκλο). Το πρότυπο περιλαμβάνει ήδη κώδικα για το χειρισμό αυτής της περίπτωσης:
    ```python
    if isinstance(input_data, dict):
        if 'data_in' in input_data:
            input_data = input_data['data_in']
    ```
    Αυτό αποτρέπει την αποτυχία του κόμβου λόγω ανακριβούς σύνδεσης.

Το πρότυπο περιλαμβάνει ήδη ένα σχολιασμένο παράδειγμα. Επιπλέον, υλοποιεί τη `get_output_for_port(self, port_name)` ώστε η μηχανή να μπορεί να δρομολογήσει κάθε έξοδο:
```python
def get_output_for_port(self, port_name):
    return self.output_data.get(port_name)
```

### 3.4. Προσαρμογή Εμφάνισης (Προαιρετικό)
Η μέθοδος `paint()` ζωγραφίζει το φόντο, τον τίτλο, την κατάσταση και οποιοδήποτε πρόσθετο κείμενο. Μπορείτε να τροποποιήσετε:
- Τα χρώματα (ενημερώνονται αυτόματα με `update_theme`).
- Το κείμενο κατάστασης (χρησιμοποιώντας το χαρακτηριστικό `self._status`).
- Πληροφορίες περίληψης (π.χ. μέγιστο μέτρου).

Το πρότυπο δείχνει ένα βασικό παράδειγμα.

### 3.5. Προσθήκη Παραμετροποιήσιμων Παραμέτρων (Προαιρετικό)
Αν ο κόμβος σας απαιτεί παραμέτρους ρυθμιζόμενες από τον χρήστη (π.χ. μέγεθος παραθύρου, συχνότητα αποκοπής), μπορείτε:
1. Να προσθέσετε χαρακτηριστικά στο `__init__` (π.χ. `self.window_size = 512`).
2. Να δημιουργήσετε έναν διάλογο διαμόρφωσης (κληρονομεί από `QDialog`).
3. Να συνδέσετε τον διάλογο στο `open_config_dialog()` (μέθοδος ήδη παρούσα στο πρότυπο).
4. Να ενημερώσετε τις παραμέτρους από τον διάλογο και να καλέσετε `self.update()`.

### 3.6. Σειριοποίηση Κόμβου (αποθήκευση / φόρτωση διαμορφώσεων)
Για να μπορεί ο κόμβος να αποθηκεύει και να ανακτά τις παραμέτρους του κατά την αντιγραφή/επικόλληση, αναίρεση/επανάληψη, ή κατά τη χρήση των εντολών Αποθήκευση/Άνοιγμα του μενού Αρχείο, πρέπει να κληρονομεί από το mixin σειριοποίησης και να δηλώνει τα χαρακτηριστικά του.

1. Εισάγετε το mixin στο αρχείο σας:
    ```python
    from nodes.serializable import SerializableMixin
    ```
2. Αλλάξτε την κληρονομικότητα της κλάσης ώστε να συμπεριλάβει το mixin πριν από το `QGraphicsObject`:
    ```python
    class MiNodoNode(SerializableMixin, QGraphicsObject):
    ```
3. Ορίστε τη λίστα `SERIALISABLE` σε επίπεδο κλάσης, με τα ονόματα των χαρακτηριστικών που θέλετε να διατηρηθούν. Υποστηρίζει μόνο απλούς τύπους (`int`, `float`, `str`, `bool`), λίστες, λεξικά, ή πίνακες NumPy (οι τελευταίοι αποθηκεύονται αυτόματα ως αρχεία `.npy` μέσα στο `.sflow`).
    ```python
    class MiNodoNode(SerializableMixin, QGraphicsObject):
        SERIALISABLE = ['frecuencia', 'amplitud', 'configuracion']
    ```
4. Βεβαιωθείτε ότι αυτά τα χαρακτηριστικά αρχικοποιούνται στο `__init__`:
    ```python
    self.frecuencia = 1000.0
    self.amplitud = 1.0
    self.configuracion = {'tipo': 'seno', 'fase': 0}
    ```

Με αυτό, δεν χρειάζεται να γράψετε μεθόδους `serialize`/`deserialize`; το mixin αναλαμβάνει αυτόματα την αποθήκευση και ανάκτηση των τιμών.

Αν ο κόμβος σας απαιτεί πρόσθετη λογική κατά τη φόρτωση (π.χ. επανασύνδεση υλικού), μπορείτε να παρακάμψετε τη `deserialize` καλώντας πρώτα τη μέθοδο του γονέα:
```python
def deserialize(self, data):
    super().deserialize(data)   # επαναφέρει τα χαρακτηριστικά από το SERIALISABLE
    self._iniciar_dispositivo()
```

## 5. Διεθνοποίηση (i18n)

Όλα τα ορατά κείμενα πρέπει να είναι μεταφράσιμα μέσω `tr("κλειδί", default="...")`. Το πρότυπο το υλοποιεί ήδη. Πρέπει να προσθέσετε τα αντίστοιχα κλειδιά στα αρχεία JSON μέσα στο `locales/`.

**Προτεινόμενη δομή:**
```json
{
   "nodes": {
     "mi_nodo": {
       "title": "Mi Nodo",
       "tooltip": "Αναδυόμενη περιγραφή",
       "ports": {
         "input": "Είσοδος",
         "output1": "Έξοδος 1",
         "output2": "Έξοδος 2"
      },
       "status": {
         "no_data": "Χωρίς δεδομένα",
         "ready": "Έτοιμο"
      },
       "menu": {
         "show_output": "Εμφάνιση εξόδου",
         "configure": "Διαμόρφωση..."
      },
       "help_title": "Βοήθεια - Mi Nodo",
       "help_html": "<h3>🎛️ Filter Node</h3>
<p>Applies a <b>digital filter</b>...</p>"
    }
  },
   "toolbar": {
     "add_mi_nodo": "Mi Nodo"
  }
}
```

Η βοήθεια HTML ακολουθεί τη μορφή τριών ενοτήτων κοινή σε όλους τους κόμβους (ειδική περιγραφή + "Πώς να σκέφτεστε το σύστημα" + "Συντομεύσεις και κόλπα"). Το πρότυπο περιλαμβάνει ήδη τη δομή στη `get_help_text()`.

## 6. Οπτικά Θέματα

Η μέθοδος `update_theme(self, theme)` λαμβάνει ένα λεξικό με τα χρώματα που ορίζονται από το τρέχον θέμα. Το πρότυπο ενημερώνει αυτόματα:
- Το φόντο του κόμβου (`node_normal_bg`)
- Το περίγραμμα (`node_selected_border`)
- Το χρώμα τίτλου και κειμένου (`node_normal_text`)
- Τα χρώματα θυρών (`port_circle`, `port_outline`, `port_inline`, `port_text`)

Βεβαιωθείτε ότι στο `MainWindow` (ή `ThemeUpdater`) καλεται `node.update_theme()` για κάθε κόμβο όταν αλλάζει το θέμα.

## 7. Λίστα Ελέγχου και Αντιμετώπιση Προβλημάτων

### ✅ Λίστα Ελέγχου
- [ ] Ο κόμβος δημιουργείται σωστά από τη γραμμή εργαλείων.
- [ ] Οι θύρες εμφανίζονται στις αναμενόμενες θέσεις και είναι ανιχνεύσιμες για συνδέσεις (`Ctrl+κλικ`).
- [ ] Κατά τη λήψη δεδομένων εισόδου, καλείται το `execute_program` και το σήμα επεξεργάζεται.
- [ ] Οι έξοδοι διαδίδονται σωστά σε συνδεδεμένους κόμβους.
- [ ] Το μενού περιβάλλοντος επιτρέπει την αλλαγή καναλιού οπτικοποίησης (αν υπάρχουν πολλαπλές έξοδοι).
- [ ] Κάνοντας κλικ στον κόμβο, γίνεται γράφημα του επιλεγμένου σήματος στο widget διαγράμματος.
- [ ] Το διπλό κλικ ανοίγει τη βοήθεια με την κατάλληλη μορφή.
- [ ] Η γλώσσα αλλάζει σωστά (κείμενα τίτλων, θυρών, μενού).
- [ ] Το θέμα αλλάζει σωστά (χρώματα κόμβου και θυρών).
- [ ] Η αντιγραφή/επικόλληση λειτουργεί χωρίς σφάλματα.

!!! tip "Ακριβής σύνδεση θυρών"
    Κατά τη σύνδεση κόμβων, βεβαιωθείτε ότι κάνετε κλικ ακριβώς πάνω στον κύκλο της θύρας προορισμού. Αν κάνετε κλικ στο σώμα του κόμβου, το σύστημα θα χρησιμοποιήσει ένα γενικό όνομα (`'data_in'`). Το πρότυπο πλέον ανέχεται αυτά τα ονόματα, αλλά είναι καλή πρακτική να συνδέεστε απευθείας στον κύκλο για να εγγυηθείτε τη σωστή δρομολόγηση πολλαπλών εξόδων.

### 🐛 Συνήθη Προβλήματα

| Σύμπτωμα | Πιθανή Αιτία | Λύση |
|---------|---------------|----------|
| Το βέλος σύνδεσης δεν αγκυρώνεται στη θύρα. | Ο κύκλος της θύρας δεν έχει `setData(0, port_name)` ή `get_port_scene_pos` δεν έχει υλοποιηθεί. | Επαληθεύστε ότι στο `_create_ports` γίνεται `circle.setData(0, port_name)` και ότι το `get_port_scene_pos` χρησιμοποιεί αυτό το όνομα. |
| Οι έξοδοι δεν φτάνουν στους συνδεδεμένους κόμβους. | Το `execute_program` δεν επιστρέφει λεξικό (για πολλαπλές εξόδους) ή το `get_output_for_port` δεν έχει υλοποιηθεί. | Βεβαιωθείτε ότι το `execute_program` επιστρέφει `{όνομα_θύρας: δεδομένα}` και ότι το `get_output_for_port` επιστρέφει την αντίστοιχη τιμή. |
| Κάνοντας κλικ στον κόμβο δεν γίνεται γράφημα. | Το `get_display_signal` δεν επιστρέφει έγκυρη πλειάδα `(x, y)` ή το `display_channel` δεν ταιριάζει με υπάρχουσα έξοδο. | Ελέγξτε ότι το `get_display_signal` χρησιμοποιεί το επιλεγμένο κανάλι και ότι τα δεδομένα είναι πίνακες NumPy. |
| Τα κείμενα δεν ενημερώνονται κατά την αλλαγή γλώσσας. | Δεν συνδέθηκε το σήμα `languageChanged` ή το `update_language` δεν ενημερώνει τα στοιχεία. | Επαληθεύστε τη σύνδεση στο `__init__`: `language_manager.languageChanged.connect(self.update_language)`. |
| Το θέμα δεν εφαρμόζεται. | Δεν καλείται το `update_theme` κατά τη δημιουργία του κόμβου ή κατά την αλλαγή θέματος. | Στο `MainWindow`, μετά τη δημιουργία του κόμβου, καλέστε `node.update_theme(self.theme_manager.current_theme())`. |
| Το βέλος δείχνει στο κέντρο του κόμβου. | Έγινε κλικ στο σώμα αντί για τον κύκλο, ή το όνομα δεν ταιριάζει με το `PORTS`. | Κάντε κλικ απευθείας στον κύκλο. Επαληθεύστε ότι το `get_port_scene_pos` έχει τον χάρτη ψευδωνύμων. |
| `NameError: name 'self' is not defined` κατά την εισαγωγή. | Δηλώθηκαν χαρακτηριστικά στιγμιότυπου εκτός του `__init__`. | Όλα τα χαρακτηριστικά όπως `self.mi_parametro` πρέπει να ορίζονται μέσα στο `__init__`. |
| Οι παράμετροι χάνονται κατά την αντιγραφή/άνοιγμα `.sflow`. | Ο κόμβος δεν κληρονομεί από `SerializableMixin` ή δεν έχει οριστεί το `SERIALISABLE`. | Υλοποιήστε το βήμα 3.6 αυτού του οδηγού. |

Ενθαρρύνεστε να συνεισφέρετε με τους δικούς σας κόμβους!
